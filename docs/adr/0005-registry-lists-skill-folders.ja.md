# 0005. サイトは登録に並んだスキルのフォルダをビルドの時に読む

## 決めること

リポジトリのスキルをどうやってサイトに載せ、サイトが宣言をどこから取得するか。

## 採った案

リポジトリごとに`registry/<owner>/<repo>.json`というファイルを1つ置き、その`skills`フィールドに、表示するスキルのフォルダをリポジトリのルートからの相対パスで並べる。
そのファイルを追加するか変更するPRを送り、このリポジトリのメンテナーがレビューする。
`node site/build.ts`は、並んだフォルダの`musubi.json`と`SKILL.md`だけをリポジトリのデフォルトブランチから読んで静的なページを書き出し、このリポジトリにはコピーを持たない。
consumerは、まず同じリポジトリにある同じ名前のproviderと結び付き、なければ登録の中でその名前を持つ唯一のスキルと結び付く。

## 却下した案

| 案 | 採らない理由 |
|---|---|
| リポジトリだけを書き、ビルドの時にリポジトリの中の`musubi.json`を全て探す | 大きいリポジトリを丸ごと読むことになり、オーナーが載せたくないスキルも載る |
| 各スキルの`musubi.json`のコピーを`registry/`に持つ | コピーが元のスキルとずれていく |
| スキルの名前を管理する中央のレジストリ | npmのようなレジストリを運用することになる。ADR 0002で、名前はインストール済みのスキルの中で解決すると決めた |

## 根拠

- Issue #3で、サイトの一覧は`registry/`へのPRで、GitHubのオーナーとリポジトリを付けて管理すると決めた。
- Issue #4の決めたことの表。登録の形式と、最初に載せるスキルと、依存を持たないコマンドでビルドするサイトを決めた。
