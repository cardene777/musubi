# 0005. 登録はスキルのフォルダを並べ、サイトは組み立ての時に読む

## 決めたこと

repoのスキルをどうやってサイトに載せ、サイトが宣言をどこから取るか。

## 選んだ案

repoごとに1つの`registry/<owner>/<repo>.json`を置き、その`skills`の欄に、見せるスキルのフォルダをrepoの根からの相対のpathで並べる。
そのfileを足すか変えるPRを送り、このrepoを持つ人が確かめる。
`node site/build.ts`は、並んだフォルダの`musubi.json`と`SKILL.md`だけをrepoの既定のbranchから読み、静的な頁を書き出し、このrepoに写しを持たない。
使う側は、同じrepoにある同じ名前の出す側に先に結び、無ければ登録の中でその名前を持つ唯一のスキルに結ぶ。

## 却下した案

| 案 | 採らない理由 |
|---|---|
| repoだけを書き、組み立ての時にrepoの中の`musubi.json`を全て探す | 大きいrepoを丸ごと読み、持ち主が載せたくないスキルも載る |
| 各スキルの`musubi.json`の写しを`registry/`に持つ | 写しが元のスキルとずれる |
| スキルの名前を持つ中央の登録先 | npmのような登録先を動かすことになる。ADR 0002は、名前を入っているスキルの中で解くと決めた |

## 拠り所

- 課題#3で、サイトの一覧は`registry/`へのPRで、GitHubの持ち主とrepoを付けて持つと決めた。
- 課題#4の決めたことの表 (登録の形、最初に載せるスキル、依存を持たない命令で組み立てるサイト)。
