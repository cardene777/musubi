# 0004. チェックはスクリプトでなくJSONのルールで書く

## 決めること

`musubi check`がconsumerに適用するチェックを、providerのスキルがどの形で書くか。

## 採った案

チェックは、必須の見出しとその順番、残してはいけない文字列 (`Fill in:`など)、表の必須の列のようなルールをJSONで書いたものにする。
`musubi check`はそのルールを読み、各consumerが指定した例に適用する。
providerのコードはconsumerの手元で実行されないので、悪意のあるチェックが紛れても何も実行されない。
チェックに書けるルールの種類は定義が定め、必要になった時に新しい種類を定義に追加する。

## 却下した案

| 案 | 採らなかった理由 |
|---|---|
| `musubi check`がproviderのスクリプトを実行する | providerのコードがconsumerの手元で実行される |
| JSONのルールを既定にし、ユーザーが許可した時だけスクリプトも実行する | providerのコードを実行する経路が残る |
| LLMに判定させる | 実行するたびに結果が変わり、実行するたびに費用がかかる |

## 根拠

- フィンガープリント (判断の記録0003) はコンテンツの書き換えに気付けるが、providerのコードの実行を安全にはしない。
