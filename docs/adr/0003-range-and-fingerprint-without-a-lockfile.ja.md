# 0003. ロックファイルを持たずにバージョンの範囲とフィンガープリントを並べて書く

## 決めること

consumerのスキルが準拠するコンテンツをどう固定し、そのコンテンツが書き換えられた時にどう気付くか。

## 採った案

consumerは、受け入れるバージョンのsemverの範囲と、最後にチェックしたコンテンツのフィンガープリントを、同じ`musubi.json`に並べて書く。
フィンガープリントは、コンテンツのファイルとチェックと、エージェントが途中で読むproviderの`SKILL.md`から求める。
`musubi check`はインストールと更新の後にフィンガープリントを比べ、一致しない時はconsumerを示して止まり、再チェックが通った時だけフィンガープリントを書き換える。
consumerの本文にも、`musubi`コマンドがある時は読む前にフィンガープリントを比べるよう、エージェントに伝える1行を置く。

## 却下した案

| 案 | 採らなかった理由 |
|---|---|
| 範囲は`musubi.json`に、チェックしたバージョンとフィンガープリントは`musubi.lock`に分けて書く | consumerが読む場所が2か所になる |
| フィンガープリントだけで固定する | フィンガープリントを書き換えるまで、修正を受け取れない |
| 範囲だけを書く | 範囲の中で書き換えられても気付けない |
| チェックする時だけフィンガープリントを比べる | インストーラーが自動でスキルを更新すると、チェックの後にコンテンツが変わる |
| コンテンツに署名する | providerがそれぞれ鍵を管理することになる |

## 根拠
