# 0002. エージェントは出す側のスキルを名前で開く

## 決めたこと

エージェントが使う側のスキルを使う時に、そのスキルが従う中身をどう見つけて読むか。

## 選んだ案

使う側の`SKILL.md`の本文が、出す側のスキルと中身を名前で書く。
エージェントは入っているスキルから出す側のスキルを名前で開き、その本文が指すfileを読む。
エージェントはこの時に`musubi.json`を読まないので、musubiの命令が無いエージェントでも同じように動く。

## 却下した案

| 案 | 採らなかった理由 |
|---|---|
| 隣のフォルダをpathで読む (`../design-doc/formats/design.md`など) | 2つのスキルが別々の所に入ると読めない。Claude Codeの2つのpluginがこれに当たる |
| musubiの命令が中身を出す | 命令が無いエージェントでは読めない |
| 入れる時に出す側の中身を使う側へ写す | 写しが元とずれる |

## 拠り所

- Claude Codeは`.claude/skills`、Codexは`.agents/skills`、Copilot CLIとGemini CLIはそれぞれのフォルダと`.agents/skills`を読み、どれも入っているスキルを名前で並べる (課題#3で調べた)。
- 定義はClaude Code以外のエージェントでも従える形に書く (`.ikkan/premises/tech.md`の8行目)。
- 課題#3の決めたことの表の3回目。
