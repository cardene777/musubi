# 0001. 宣言はmusubi.jsonに書く

## 決めること

providerとconsumerのスキルが、musubiの宣言をどこに書くか。

## 採った案

`SKILL.md`の隣に別の`musubi.json`を置き、`provides`と`follows`を構造化したJSONで書いて、JSON Schemaで検証する。
`SKILL.md`は、Agent Skillsの仕様が定める形のままにする。

## 却下した案

| 案 | 採らなかった理由 |
|---|---|
| `SKILL.md`のフロントマターの`metadata`に書く | 値は文字列だけなので、準拠するコンテンツの一覧を1つの文字列に詰め込むことになる |
| `requires`のような新しいフィールドをフロントマターに追加する | Agent Skillsのリファレンスの検証ツールは、知っている6つ以外のフィールドを拒否する。仕様が変わるまで、スキルが検証を通らなくなる |
| `SKILL.md`の本文の節に書く | 機械で読むには、本文の書き方にルールが必要になる |

## 根拠

- Agent Skillsの仕様は`metadata`を文字列から文字列へのマップと定めており、リファレンスの検証ツールは知らないトップレベルのフィールドを拒否する (Issue #3で調べた)。
- 定義は、Claude Code以外のエージェントでも使える形にする (`.ikkan/premises/tech.md`の8行目)。
- Issue #3の決めたことの表の1回目。
