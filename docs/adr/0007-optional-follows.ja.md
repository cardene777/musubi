# 0007. providerが無くても動くconsumerは準拠を任意にする

## 決めること

providerのスキルがインストールされている時だけ使うコンテンツに、consumerがどう準拠するか。
たとえば、無くてもスキルが動く書き方のルールがこれに当たる。

## 採った案

定義のバージョン`2026-11-20`で`follows.<参照>.optional`を加え、`true`を書いた準拠を任意の準拠とする。
任意の準拠のproviderがインストールされていない時、`musubi check`は警告を出してその準拠を飛ばし、エージェントはそのコンテンツ無しで作業を続ける。
providerがインストールされている時、`musubi check`はほかの準拠と同じように範囲とフィンガープリントと例を確かめる。
`musubi add <スキル名>/<名前> --optional`は`optional: true`を書き、`musubi`が古い日付なら`2026-11-20`に上げ、providerがインストールされている時だけコンテンツを読む3行を出力する。
`2026-11-19`を書いた`musubi.json`は今も通り、その中の`optional`は知らないフィールドとして拒否する。
サイトの一覧とスキルのページは、任意の準拠に印を付ける。

## 却下した案

| 案 | 採らない理由 |
|---|---|
| 日付を上げずに`2026-11-19`へ`optional`を足す | npmのmusubi-cli 0.1.0はこのフィールドを知らないフィールドとして拒否し、新しい定義が要ることが伝わらない |
| providerが、コンテンツを任意で提供すると宣言する | providerが無くても動けるかは、consumerにしか分からない |
| 任意の準拠のproviderが無い時も`musubi check`を失敗させる | providerを入れていない人の`musubi check`が、無くても動くスキルのために失敗する |
| `musubi graph`とサイトの図で、任意の準拠を点線で描く | 図の線はもともと破線で動いており、点線と見分けにくい。一覧とスキルのページの印で見分けられる |

## 根拠

- Issue #29の決めたことの表。オーナーは2026-11-20に、agent-shurikenの`convey`スキルを`japanese-writing`の書き方のルールに結ぶ前に、定義へ任意の準拠を足すと決めた。
- 定義のバージョンは日付で表し、`musubi check`は知らない日付を拒否するので、フィールドを足す時は日付も上げる。
